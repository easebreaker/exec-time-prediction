## 〇、结论摘要

1. **复杂度不是解析式的，而是「台阶 + 分段线性 + 两个 regime 的较大者」。** 昇腾上的四个来源：16×16 分形对齐、Tiling 的块数与波次、存储层级的算术强度拐点、动态 shape 的逐算子下发。任何单一幂律都只是这四者在某一区间的近似。🟢
2. **本批 attn 实现在小长度上的「负收益」，机制上可由分形与 Tiling 量化解释，而非增长律本身为负。** cp2/cp4/cp8 在 L=256 时 Query 侧分别只有 128/64/32 行，按 128 行基本块计都只占 **1 个 Q tile**，计算量相同；实测 9.75 / 11.68 / 11.76 ms，cp4 与 cp8 仅差 0.7%，与该推断一致。🔵（判据见 §4.1）
3. **固定项 b 与长度无关，因此它不可能是「计算」项，只能是「下发 + 同步 + 建链」项。** 官方明确：动态 shape 下每个算子要经 InferShape、Tiling、AllocMem、Launch 四个 Host Kernel，复杂算子 Tiling 可达数十微秒。🟢
4. **b 在 L=256 时占 90%，于是小段误差几乎全部由 b 的估计精度决定。** 这不是「形式不够」，而是「把可以通过插桩直接测到的量拿去拟合了」。🔵
5. **有效 ρ 从 0 漂到 1.4，主体成因是截距稀释，不是增长律在变。** 以 `b + cL²` 预测的局部指数为 0.11/0.38/0.96/1.58，观测为 0.19/0.41/1.05/1.39：前三段吻合，最大尺度上观测**低于**二次，说明大 L 上还有一条指数为 1 的搬运项。🔵（判据见 §4.3）
6. **拟合方案应改三处**：① 主项由「L 的幂」改为「计算项与搬运项取较大者」的加法上界；② 长度轴在 L 小于约 512 时换成 `ceil(L/16)·16`（分形对齐），并把基本块当登记量而非拟合量；③ b 从拟合参数改为由 kernel 数推出的量（`b = n_kernel · c_dispatch`）或至少 `b₀ + b₁·N`。🔵

## 二、四个「复杂度发生器」

这一节是全文的骨架：昇腾上任何算子的时间都由下面四件事共同决定，而它们各自的数学形式不同。

### 2.1 分形对齐：先把 16 变成 1

Cube 每次吃 16×16 的分形块。fp16 下 M、N 两个轴都向上补齐到 16 的倍数：

```
M' = ceil(M/16)·16 ,  N' = ceil(N/16)·16
```

🟢 官方文档给出的例子：M=40、K=56 的矩阵搬到 L1 时被补成 48×64。

**含义**：任何 `M·N` 形式的项，严格写都应是 `M'·N'`。这个差异在 M ≫ 16 时是 O(16/M) 的相对误差（M=256 时 6%，M=1024 时 1.6%），但在 M < 128 时是数倍。**因此「小长度」与「大长度」不该用同一个形式。**

### 2.2 Tiling：块数与波次，产生台阶与分段线性

一个 M×N×K 的 MatMul 在单核上的时间是

```
T ≈ ceil(M/BM) · ceil(N/BN) · ceil(K/BK) · t_block  +  t_loop
```

其中 `t_block` 由 baseM/baseN/baseK 决定（官方案例：base 块从 64 提到 128，循环数减半，性能翻倍；基本块再优化后 MTE2 从 2452 μs 降到 808 μs 🟢）。多核时再叠一层波次量化：

```
T ≈ ceil( (块数) / 核数 ) · t_wave
```

**含义**：这是一个**台阶函数**，台阶宽度由基本块与核数决定。它同时产生两种「看起来像物理规律」的假象：

- 在块数少于核数时，时间几乎不随规模变化（并行度不足，只有一波）；
- 跨过整数倍时出现跳变（`ceil` 的断点）。

FlashAttention 的官方优化案例里，causal mask 下「红色块要算、绿色块不算」，按行分核会导致 1 块 vs 8 块的严重不均衡，改为按块分核后性能翻倍 🟢。**这说明核内确实按块跳过被完全屏蔽的 tile** —— 这一点决定了组内注意力（block-diagonal）到底该记成 `L·T` 还是 `L²`（见 §3.5）。

### 2.3 存储层级：算术强度决定「谁是主项」

一次 kernel 的时间约为

```
T ≈ max( FLOPs / P_eff ,  Bytes / BW_eff )
```

拐点（ridge point）由片上或 HBM 的带宽决定。以 910B3 量级估算：

| 带宽口径 | P（fp16） | ridge = 2P/BW（attention 的 L_star） |
| --- | --- | --- |
| HBM 1.6 TB/s | 245–295 TFLOPS | **306–369** |
| HBM 392 GB/s（若该口径成立） | 245 TFLOPS | **1250** |

🔵 推导：`T_c = 4BhL²d_h/P`，`T_m = 8BhLd_h/BW`（Q/K/V/O 各一遍，fp16），令二者相等得 `L* = 2P/BW`。

**含义一**：`L* ≈ 300–1200`。小于它时 attention 是访存 bound（时间近似 ∝ L），大于它时是计算 bound（近似 ∝ L²）。这正是「有效指数从 1 漂到 2」最自然的物理解释，也与观测到的转正区间（4096 以上）量级相符。

**含义二**：L1 是 512 KB/核、L2 是 192 MB 全芯片共享。基本块 128×128×fp16 = 32 KB，Q tile 常驻 L1、K/V 走着看；只要一个 batch 的 K/V 总量小于 L2（192 MB），它就是 L2 bound 而不是 HBM bound，此时 ridge 降到约 2·295/7 ≈ 84，attention 转为计算 bound。**所以「同一个算子在不同 L 上 regime 不同」不是噪声，而是层级切换。**

### 2.4 下发：与 L 无关、与 kernel 数成正比的那一项

动态 shape 下，一个 AI Core 算子的下发被拆成四个 Host Kernel：InferShape、Tiling、AllocMemHbm、Launch；**复杂算子的 Tiling 计算可达数十微秒**；Host 下发慢于 Device 执行时形成 Host Bound，Device 出现空闲 🟢。官方给出的对照：小 shape 的 Gather/Concat 保留在 Host 执行后，该片段的端到端从 3 ms 降到 10 μs；LLaMA2 上符合条件的算子有 650+ 个，整网 1.062 s → 1.009 s 🟢。

**含义**：截距项的真实形式是

```
b = n_kernel · (t_launch + t_tiling + t_alloc)  +  n_sync · t_sync
```

`n_kernel` 只随「层数 × 每层算子数 × 是否插桩」变化，**与 L 无关**。这解释了为什么 b 能在 L 从 256 到 16384 的 64 倍范围内保持同一量级。

### 2.5 集合通信：α–β，两个系数物理意义不同

HCCL 的通用模型是 `T = s·α + (N/P_eff)·β`，`s` 是轮数、`α` 是每轮建链/同步延迟、`β` 是每字节代价；小包时 `s·α` 主导，大包时带宽主导 🟢。官方另一处直接写明：通信域初始化、建链、销毁是**固定开销**，小包高频时它远大于数据本身的传输时间。

**含义**：`τ + v·V` 不是「拆成两项更灵活」，而是 α–β 模型的直接对应物：`τ = s·α`（与字节数无关，与轮数成正比），`v = β`。**因此 τ 应当随 N 变化**（`s` 随算法变化：Ring 是 N−1 轮，Butterfly 是 log N 轮），这与 S18 的实测「b 随 N 上升」在方向上一致；而 v 应当与 N 基本无关 —— 实测里 κ≈0、v 接近常数的结果与此相符。

## 三、逐算子：优化形式 → 复杂度形式 → 拟合含义

对 `stage.py` 的 7 类算子逐个过一遍。「复杂度形式」一列是可以直接写进登记表的式子，不是拟合结果。

### 3.1 lookup（查表 / GatherV2）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | 按行 gather，纯访存；无 Cube 参与。随机索引导致相邻线程访问不同行，**访存难合并**；官方给出的优化是调整切分让同一 Warp 访问同一行的相邻列，实测 4886 → 866 μs（−82%）🟢 |
| 其他优化 | 与后续 MatMul 融合（省掉中间结果写回）；重复索引 unique 去重（工业实现中重复率 30%+）🟡；小 shape 时留在 Host 执行 🟢 |
| 复杂度形式 | `T ≈ Bytes/BW_eff = B·n_id·d·s / BW_eff`，**线性、无二次项、与 L 无关** |
| 与现模型 | 现模型主项 `B·n_id`（d 与字节宽度被 θ 吸收），方向正确 |
| 拟合建议 | ① **表是否落进 L2 是一个断点**：`n_id·d·s ≤ 192 MB` 时是 L2 bound，超过后是 HBM 随机访问 bound，单位字节代价会跳变；d=128、fp16 时阈值约 75 万行。建议在登记表里加一列「表是否驻留 L2」，两段分别估 θ。② EmbP 切表后若需 All-to-All 交换，必须补 `τ + v·V` 项；现模型 `embp` 只给了 lookup 的 `1/N` 缩放，没有通信项，会低估。 |

### 3.2 linear（线性投影 / MatMul）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | Cube + NZ 分形；Tiling 参数 baseM/baseN/baseK；大包搬运；分核（案例中 blockDim 4→20 得 4.75×）🟢 |
| 复杂度形式 | `T ≈ max( 2·N_tok·d·d_hid/P_eff , Bytes/BW )`，其中 `Bytes ≈ (N_tok·d + d·d_hid + N_tok·d_hid)·s` |
| 关键推论 | `N_tok` 小到权重搬入占优时，时间是**常数**（与 N_tok 无关）；`N_tok` 大时才是线性。即 `θ_linear` 不是常数，而是 `a/N_tok + b` 的形状。**但 d、d_hid 固定后，`a` 这一支只有几十 KB，落在 b 里；所以现模型在主项上用 `N_tok·d·d_hid` 是安全的，前提是 b 允许吸收它。** |
| 拟合建议 | ① 保持线性主项；② 若换到 d_hid 很小（< 256）的模型，分形利用率下降（`ceil(d_hid/16)·16 / d_hid`），θ 会随 d_hid 非光滑变化，**这时不能跨模型复用 θ**；③ `ceil(N_tok/16)` 只在 N_tok < 64 时有意义（GR 的短序列段会命中）。 |

### 3.3 self_attn（融合注意力）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | `npu_fusion_attention`（BNSD），内部即 FlashAttention：Q 常驻 L1、K/V 分块、在线 softmax（维护 m、l、acc）、CV 流水 🟢🟡 |
| 关键优化 | 基本块 64→128 循环数减半、性能翻倍；causal 下按块分核做负载均衡；`sparse_mode` 稀疏模式；`actual_seq_qlen/actual_seq_kvlen` 变长模式；`pre_tockens/next_tockens` 滑窗 🟢🟡 |
| 复杂度形式 | `T ≈ max( σ·4·B·h·L²·d_h / P_eff , 8·B·h·L·d_h / BW ) + 逐块固定开销·块数`，`σ` 为稀疏度（causal=0.5，滑窗≈w/L，全注意力=1） |
| 与现模型 | 现模型 `self_attn = B·h·L²·d_head`，取 σ=1。**若实现是 causal，这一项会系统性高估 2 倍**；若走 `sparse_mode=3`，官方口径节省约 50% 🟡 |
| 拟合建议 | ① 把 `σ` 作为**登记量**而非拟合量（与 ρ 的处理一致）；② **主项改为 max(计算项, 搬运项)，或两项相加作为上界** —— 理由见 §2.3：小 L 时搬运项主导，这正是当前有效指数小于 2 的物理来源；③ L < 512 时把 L 换成 `ceil(L/16)·16`。 |

### 3.4 cross_attn（交叉注意力 / 增量注意力）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | 同一族算子可分两种：全量 FA（prefill 风格，Q、KV 都是矩阵）与增量注意力（decode 风格，读 KV cache）。后者在 Ascend 上是独立算子（`npu_incre_flash_attention` / paged attention），**成本 ∝ 读 KV 的字节数，即 ∝ L_kv，而不是 ∝ N_q·L_kv 的乘积**（N_q 很小时）🟡 |
| 复杂度形式 | prefill 风格：`T ∝ B·N_q·L_kv·d`；decode 风格：`T ∝ B·L_kv·d·s / BW`（与 N_q 基本无关，只受带宽支配） |
| 与现模型 | 现模型统一写 `B·N_q·L_kv·d`。对 HyFormer 的 decode（N_q = short_len）在 short_len 很小（如 16）时，会高估一个量级的斜率 |
| 拟合建议 | 在登记表里为 cross_attn 增加一列「prefill / decode」；decode 型主项改为 `B·L_kv·d`（去掉 N_q），并配一个「N_q 独立于成本」的判据：扫 short_len 时 seq_cross 只动 query、decode 动 Q 与 KV，二者斜率应当不同（现指南已有此设计，正好可以判定）。 |

### 3.5 group_attn / token_gemm（组内注意力与 token 轴矩阵乘）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | 两条路：① 按组做**批量 FA**（B·R 个长度 T 的序列），成本 `R·T²`；② 做一次全注意力再用 block-diagonal mask，成本 `L²`（但被完全屏蔽的 tile 会被跳过，实际约 `R·T² + 边界`） |
| 复杂度形式 | 批量 FA：`T ∝ R·T²·d = L·T·d`（**对 L 线性**）；全注意力 + mask：`T ∝ L²·d`（对 L 二次） |
| 与现模型 | 现模型 `token_square = B·R·T²·d`，`groups_follow_length` 时 R=L/T，即 `L·T·d`。**取的是批量 FA 一支** |
| 拟合建议 | 这一项不用拟合，**用「斜率比」判定**：R 固定、只动 L 时，若时间不随 L 动 → 批量 FA；若随 L 线性增长 → 全注意力加 mask。`复杂度测定-模型指南.md` 里 LONGER 的「次数接近 1 还是 2」判据就是这个，**建议把它从「拟合后看系数」提前到「测量前先判定」**，能省掉两种形式各测一遍。 |

### 3.6 token_permute（转置 / 重排）

| 项 | 内容 |
| --- | --- |
| 昇腾上的实现 | 无 Cube 参与，纯搬运 + UB 内重排；难点是访存合并与 **UB bank 冲突**：同一个 32×32 转置，去掉 bank 冲突后 23.9 → 15.2 μs（−37%）🟢 |
| 关键事实 | 「TransData 通常比 Conv/MatMul 还耗时」，且常被图融合消掉 🟢 |
| 复杂度形式 | `T ∝ Bytes = B·T·d·s`，**无计算项**；若被融合，则**该项为 0** |
| 拟合建议 | 这一项不该有连续系数，应当登记为**二值**：「融合 / 未融合」。当前把它当成 9 个单项之一去拟合，等价于给一个离散事实配一个连续数 —— 这正是 S22「不要为档位付参数」的同一条理由。 |

### 3.7 intercept（截距）

| 项 | 内容 |
| --- | --- |
| 物理内容 | 逐算子 InferShape + Tiling + AllocMem + Launch；流同步；集合通信建链（每轮 α） |
| 形式 | `b = n_kernel·c_dispatch + n_sync·t_sync + n_round·α`，**与 L 无关** |
| 估计方式 | **不拟合，直接测**：profiler 的 `op_summary.csv` 给出 kernel 数与每 kernel 时间，减去各段计算项即得；或做「层数减半」实验，看 b 是否随 kernel 数减半 |
| 与现模型 | 现模型把 b 当拟合参数，这是 S19「一个 b 服务三档」的根源之一 —— 它不是同一个物理量在三档上取值不同，而是三档的 kernel 数与轮数本来就不同 |

## 四、用本批实测检验机理

数据：`实验数据-分析.md` 第五、六节，MTGR attn，cp2/cp4/cp8 × 13 个长度。

### 4.1 小长度负收益 = 量化，不是增长律为负

L=256 时，Query 侧行数为 L/N = 128 / 64 / 32。按 128 行基本块计：

| N | Q 行数 | Q tile 数 | K tile 数 | 计算块数（相对 cp2） | 实测（ms） |
| --- | --- | --- | --- | --- | --- |
| cp2 | 128 | 1 | 2 | 1.00 | 9.75 |
| cp4 | 64 | 1 | 2 | 1.00 | 11.68 |
| cp8 | 32 | 1 | 2 | 1.00 | 11.76 |

**cp4 与 cp8 只差 0.7%，cp2 也仅低 16%**（低的部分可由「每卡仍要读整段 K/V」与通信解释）。若计算真按 `L/N` 连续缩放，cp8 应比 cp2 快约 4 倍。**观测到的「越快越慢」正是「量化后根本没有变快」加上「通信与同步变多」。**

> 判据（可立即做，不需要新硬件）：把同一组点用 `L=2176`（17 个 128 块）与 `L=2304`（18 个块）各跑一次。若时间随块数**阶梯**上升而在块内平坦，则量化成立；若平滑上升，则不成立。

### 4.2 b 的三分：哪一部分是下发

现有拟合给出 b = 8.80 / 10.71 / 12.32 ms，且 θ₁ 为负（即曲线在 L≈59 处取极小）。负的线性项是「小段近乎平坦 + 大段上翘」的拟合副产物，物理上并不存在负的线性项。

**候选分解**（按可测性排序）：

| 成分 | 是否随 N 变 | 是否随层数变 | 如何单独测 |
| --- | --- | --- | --- |
| 逐 kernel 下发（Tiling + Launch） | 略微（每卡 kernel 数不变，但集合通信算子增加） | **是，线性** | 1 层 vs 4 层；看 b 是否 ≈ 4× |
| 集合通信建链（n_round·α） | **是**（Ring 为 N−1 轮，Butterfly 为 log N 轮） | 是（每层都要） | 固定 L，扫 N=1/2/4/8；b 的增量应呈阶梯 |
| 测时同步 / flush | 否 | 否 | 去掉每次迭代的 synchronize 再测 |
| 未切分 KV 的搬运 | 是（每卡都读全量 KV） | 是 | 该项 ∝ L，应出现在 θ₁ 而不是 b；若 b 随 L 不变，可排除 |

🔵 若第一行成立，则 `b` 可以由「kernel 数 × 单 kernel 下发代价」算出，**不必拟合**；这也直接解释 S19 的「共享 b 必须折中」——三档的 kernel 数与通信轮数不同，本来就不是同一个 b。

### 4.3 有效 ρ 的漂移：三个可分离的成因

对 cp2 的实测取相邻两点的局部指数（取区间几何中点处的值）：

| 区间 | 1024→2048 | 2048→4096 | 4096→8192 | 8192→16384 |
| --- | --- | --- | --- | --- |
| 观测局部指数 | 0.19 | 0.41 | 1.05 | 1.39 |
| `b + cL²` 预测（b=8.3） | 0.11 | 0.38 | 0.96 | 1.58 |

（`c` 由最大点定：`c = (69.98 − 8.3)/16384² = 2.30e−7`。）

三个候选机制各自的预期：

1. **截距稀释**：若 `T = b + c·L^p`，局部指数 `= p·cL^p/(b+cL^p)`，随 L 从 0 单调升到 p。上一表的预测列即 p=2 的情形。
2. **tile 量化**：台阶使局部指数在断点附近跳变，取值在 0.5–2 之间抖动，但不产生系统性增长。
3. **regime 切换**：`L_star≈300–1200` 之后由搬运 bound 转计算 bound，局部指数从 1 趋向 2。

**结论（与最初设想相反，需按数据修正）**：前三段预测与观测只差 0.02–0.09，**说明 0→1 的漂移几乎全部由截距稀释解释，不需要引入新机制**；而 8192→16384 上观测 1.39 **低于** 预测 1.58，即最大尺度上的增长**弱于二次**。因此：

- 漂移的**主体**是「b 占比下降」，不是增长律在变 —— 这与 S14 目前「真实曲线在两档之间连续移动」的叙述不同，应改为「截距稀释 + 大尺度上弱于二次」。
- 大尺度弱于二次，与 §3.3 的 `max(计算, 搬运)` 形式一致：搬运项的指数为 1，占比越高，合成指数越低；也与 tile 化下 `ceil(L/BM)·ceil(L/BN)` 的线性边界项同向。**两条机制都指向「主项应当是两项之和/较大者，而不是单一 L 的幂」。**

> 判据：把 b 用 profiler 直接测出并固定，再拟合指数。若残差的局部指数在小段变为 ~1.8–2.0，则小段漂移是截距造成；若 8192→16384 仍显著低于 2，则「弱于二次」成立，需要保留搬运项。

### 4.4 一个必须说清的噪声问题

小段 6 个点（256–1536）的 cp2 实测为 9.75 / 8.53 / 8.68 / 11.02 / 8.51 / 8.33 ms：均值 9.14、标准差 1.05、**变异系数 11.5%**。而小段 MAPE 30.1% 对应约 2.7 ms 的误差。

即：**模型误差约为同点重复波动的 2.6 倍。** 结论「小段误差大」仍然成立，但其中有多少可归因于形式、多少是单次测量的抖动，目前分不开。cp4 在 L=512 的 13.51 ms 与相邻两点（11.05、9.32）相比是明显离群点，支持「小段测量抖动偏大」的判断。

**代价最低的改进**：小段 6 个点各重复 5 次取中位数，并报 IQR。这一步不做，后续所有关于「分段误差」的结论都带着一个未量化的方差项。

## 五、复杂度拟合方案 v2

在上述机理基础上，对现有 9 项形式做最小必要修订（不是推翻，是把「该登记的量」与「该拟合的量」分开）。

### 5.1 形式修订

```
T_i(x,p) = b_i(N, n_kernel)                              # 由测量得出，不拟合
         + Σ_k [ θ_ik · f_k(x) ]                          # 计算项（保留）
         + Σ_k [ β_ik · bytes_k(x,p) ]                    # 新增：搬运项
         + σ_i · (被切分项按 s_kp(N) 缩放)                  # 保留
         + τ_i(N) + v_i · V_i(p)                          # 通信：α–β
```

- **新增搬运项并不破坏「结构解析、系数经验」**：bytes 由形状唯一决定，只有一个系数 β，且可解释为「每字节的等效时间」。它是 b 的物理对手：当计算项小于搬运项时，主项自然切到 β·bytes，无需引入 max（相加即上界，与他们已有的「逐段相加是上界」口径一致）。
- **`f_k(x)` 在 L < 512 时改用分形对齐量**：`ceil(B·h·L/16)·16` 之类；或保留原式但在登记表里注明「小段另有 ≤ 6% 对齐残差」。
- **σ（稀疏度）作为登记量**：causal 0.5、滑窗 w/L、block-diagonal 1/T。它与 ρ 同一性质 —— 由实现定义，不由数据定。

### 5.2 该登记、不该拟合的量（与 S22 判据同一逻辑）

| 量 | 现状 | 建议 | 理由 |
| --- | --- | --- | --- |
| 缩放指数 ρ | 已登记 | 保持 | 由切分定义决定 |
| 稀疏度 σ（causal/窗口/分块） | 隐含为 1 | 登记 | 由 mask 与 kernel 是否跳块决定 |
| 分形对齐与基本块 | 无 | 登记 BM、BN | 由 kernel 实现决定，非拟合对象 |
| permute 是否融合 | 当连续系数拟合 | 二值登记 | 融合是编译决策 |
| 截距 b | 拟合 | 测 kernel 数 | 见 §4.2 |
| τ 的轮数 s | 常数 | 登记为算法函数（Ring: N−1；Butterfly: log₂N） | 由 HCCL 算法决定 |

### 5.3 b 的两种写法（按可得性二选一）

- **有 profiler 时**：`b = Σ_kernel (t_launch + t_tiling + t_alloc) + n_sync·t_sync`，直接从 `op_summary.csv` 汇总，不进拟合。
- **无 profiler 时**：`b(N) = b₀ + b₁·N`（即 S21 的折中方案），并把 b₁ 解释为「每加一档并行度多出的集合通信轮次与建链代价」，而不是纯经验斜率。

### 5.4 与现有结论的兼容性检查

- S17「小长度上切得越多反而越慢」→ **更强**：现在有了机制（tile 量化），不再只是现象。
- S18「b 随 N 上升，而 τ 是常数」→ **更强**：τ 本来就不是常数，α–β 模型里 `τ = s·α` 随轮数变。
- S19「共享 b 只能折中」→ **更强**：三档 kernel 数与轮数不同，b 不同是必然。
- S20「分度拟合更准但退化」→ **不变**：分度拟合治的是 b，而 b 可以直接测，所以分度拟合的必要性进一步下降。
- S21「b₀ + b₁·N，4 个参数」→ **不变**，但 b₁ 有了物理解释。
- S13/S16「必须分段报告」→ **不变**，且多一个理由：不同段的 regime 不同（搬运 bound / 计算 bound）。

## 七、对汇报的直接可用表述（供改稿时取用）

- 「有效指数为负」→ 「**并行度提高后计算量没有减少**：小长度上 Query 侧不足一个基本块，切分只是把同一块拆到更多卡上，而通信与同步增加」。
- 「b 是固定项」→ 「b 是**下发与建链**项：动态 shape 下每个算子要经 InferShape、Tiling、AllocMem、Launch，复杂算子的 Tiling 可达数十微秒；它与长度无关，与 kernel 数和通信轮数有关」。
- 「增长律从 1 漂到 2」→ 「**同一算子的实测增长指数随 L 上升，主体原因是固定项占比在下降**：以小段实测的固定项 8.3 ms 与 `b + cL²` 复算，局部指数应为 0.11/0.38/0.96/1.58，与观测的 0.19/0.41/1.05/1.39 基本吻合；最大尺度上观测低于二次，说明还有一条指数为 1 的搬运项。因此主项应写成「计算项 + 搬运项」，而不是单取某一档幂次」。
- 「τ 与 v·V」→ 「这是 HCCL 的 α–β 模型：τ=s·α 是轮数乘建链延迟，v=β 是每字节代价；前者随 N 变，后者不变」。
