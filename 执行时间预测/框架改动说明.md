# 框架改动说明（算子分类 v2）

> 对应手册：`文档/算子复杂度-按算子手册.md`。本文只写**代码里改了什么、为什么**，
> 以及在哪些地方向后兼容。改完共 67 项测试通过（原 47 + 新增 20）。

---

## 一、算子：7 → 11

`timepred/stage.py` 的 `OPERATORS` 新增四类，全部按手册的章节命名：

| 算子 | 主项 | 为什么必须有 |
|---|---|---|
| `elemwise` | `2·N_tok·d` 与 `2·B·h·L²` | 每层都有 norm/激活；HSTU 还对 S×S 做一次 SiLU，那是 L² 阶 |
| `moe_gate` | `B·L·N_exp` | 成本由专家数决定，与 L 无关 |
| `moe_comm` | `B·L·topk` | EP>1 时每层两次 AllToAllV，且是变长的 |
| `score_gemm` | `N_user·N_item·d` | 全库打分，`N_item` 百万级，形状与前面所有算子都不同 |

新增单项（`FEATURE_ORDER`，追加在末尾，不影响旧列顺序）：
`elemwise_linear`、`elemwise_square`、`gate_score`、`gate_sort`、`moe_route`、`score`、`tile`。

## 二、轴：5 → 7

`_LOAD_FIELDS` 与 `StageLoad` 新增 `n_exp`、`topk`、`n_user`、`n_item`、`n_probe`。
`complexity_grid` 里 `n_exp` 与 `n_item` 各加一条扫描线，否则这两类算子没有自变量。

## 三、登记位（不可拟合，全是实现事实）

`StageSpec` 新增 8 个字段，默认值都保持旧行为：

| 字段 | 取值 | 作用 |
|---|---|---|
| `impl` | `auto`/`A`/`B`/`C` | 记录实现路径，供人工核对 |
| `fused` | 布尔 | 为真时整段所有列为 0（被相邻 kernel 吸收） |
| `sparse` | `(0, 1]` | 块级跳过后的有效比例 σ，乘在 L² 项上 |
| `block_m` / `block_n` | 整数 | 基本块；`model="tile"` 时替代 L 的幂 |
| `model` | `power`/`tile` | 复杂度模型 |
| `intercept_mode` | `stage`/`network` | 截距留在段内，还是提到网络层 |
| `renorm` | `0`/`1` | 门控是先 softmax 再 top-k，还是反过来 |
| `kernels_per_layer` | 整数 | 网络层固定开销的自变量 |
| `value_dim` | 整数 | 注意力的 V 维；非 0 时 L² 项宽度取 `d_head + value_dim` |

`StageSplit` 新增 `span`（`intra`/`cross`），`SplitReport` 新增 `v_cross_s_per_byte`
与 `v_for_span()`。样本含两种跨度时，`fit_split` 会把 `v` 拆成 `v@intra` 与 `v@cross`
两列分别估；只有一种跨度时行为与旧版完全一致。

## 四、网络层截距

新函数 `kernel_count(stages)` = `Σ n_layers × kernels_per_layer`（融合段跳过）。
`NetworkFacts(fixed_s, dispatch_s, sync_s, n_sync)` 给出
`b = fixed + dispatch·kernel 数 + sync·同步次数`。
`predict_network(..., network=facts)` 把它加在逐段之和之外；
若某段用 `intercept_mode="network"`，该段的 `intercept` 列为 0，避免重复计入。

理由：`b` 与长度无关，只与 kernel 数和通信轮数有关（手册 §2.4、§4.2）。

## 五、新配方

`recipes.py` 追加四个构造函数，旧的 `hstu_stages` 等签名与返回值**未改**（测试仍解包三元组）：

| 函数 | 段 | 用途 |
|---|---|---|
| `hstu_stages_with_elemwise()` | 6 段，其中 3 段 `fused=True` | 融合开启时与 `hstu_stages` 数值完全相同；关闭后多出 27% |
| `hstu_stages_tiled()` | 3 段，注意力用 `model="tile"` | 块计数模型 |
| `moe_ffn_stages()` | 门控 → 分发 → 专家 FFN → 合并 → 逐元素 | MoE 一层 |
| `retrieval_stages()` | 用户塔 + 全库打分 | 召回一步 |

## 六、测量计划

`plan.py` 的 `all_requests()` 仍为 **88 条**（未动）。新增两个可选家族：

- `moe_requests()`：11 条，专家数扫描 + EP 并行度 × 跨度 + 一条换长度样本（用于把 V 与 token 数分开）。
- `retrieval_requests()`：4 条，商品数扫描，最后一条留出。

`MeasureRequest` 增加 `n_exp`/`topk`/`n_item` 三个可选字段；
`stage_io.py` 的模板与读取同步加列，旧表缺列时取默认值。

## 七、演示与核对

```bash
cd 执行时间预测
python3 -m timepred.flow_demo      # 七步全流程，约 1 秒
cd .. && python3 _vendor/hstu_probe.py   # 官方 HSTU 单层形状核对（需 torch）
```

`flow_demo` 的第 3、4 步用实测（`data/attn_mtgr_cp13.csv`），其余标注 `[合成]`。
第 7 步调 `hstu_probe`；没有 torch 或沙箱限制 libomp 时自动跳过，不中断。
